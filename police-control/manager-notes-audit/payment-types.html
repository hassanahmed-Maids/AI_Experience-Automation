Read the verdict column carefully — four of these are not findings

CLEARED means every test that could run passed. It does not mean audited: group entitlement rules are separate, and several types have none that can run yet. CANDIDATES are real populations awaiting an input. A type with no findings has not been proven correct.

Fourteen candidate findings were raised and withdrawn during this audit — roughly twenty dirhams withdrawn for every one confirmed. Every finding built on a proxy shrank when the real classifier arrived; none grew. The ones that held were measured directly against a rule the code or the business states.

What this page excludes, priced

Future-dated notes. Every test filters NOTE_DATE <= CURRENT_DATE(), which removes 216 airfare notes / AED 385,000 dated as far ahead as 2028-06-02. Never failed, never passed, never examined.

Everything before September 2025. The window is twelve months of roughly four years. For Bonus alone that leaves AED 1,992,552 — 70% of every bonus dirham ever paid — outside the audit entirely.

Deductions. NOTE_TYPE = 'ADDITION' appears in 151 query blocks. Money taken from a maid has never been examined by anything.

The finding that outlives the numbers

Current state is not history. Six findings rested on a column describing a maid today, standing in for what was true on the day she was paid. Every one moved when a log replaced the column — airfare 137,500 → 4,500, bonus 143,965 → candidates, raffle 3,000 → 0, relocation 4,700 → 3,900, anti-attrition 2,476 → 5,726, office work a clear → void. Four shrank, one grew, one inverted.

Anything in the company reading HOUSEMAIDS_INFO to describe a past date is wrong the same way. The fix is one join pattern against HOUSEMAID_STATUS_LOGS and HOUSEMAID_TYPE_LOGS, which are interval tables.
